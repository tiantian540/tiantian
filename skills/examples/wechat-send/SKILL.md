# 微信发消息

目标：把用户给的某条内容，发给用户指定的那个人，发送前停下来确认。只做单聊，不主动发群聊。

1. 先确定「收件人」和「消息内容」。优先级：用户本次说的 > 记忆里已有的（如常用联系人）> 都没有就问用户。缺收件人、缺内容、或联系人同名无法区分时，一次 ask_user 问清，不要猜，也不要用相似名字代替。
2. 启动微信（com.tencent.mm）。需要登录、出现验证码、提示新设备验证或多设备登录冲突时，立刻 ask_user 让用户接管处理；处理完再继续，不能把「跳过登录」当成已登录。
3. 在顶部搜索框输入收件人名称，在搜索结果里找到并进入与这个人的单聊。进入后核对会话标题就是这个人；点错会话要退出重进，不要在当前会话里继续。
4. 搜索结果里出现同名联系人、群聊重名、或「联系人/群聊/聊天记录」多类结果混在一起时，停下来问用户选哪一个，不要自己挑第一个。对方不是好友、需要发送验证申请时，说明情况并问用户是否继续。
5. 在底部输入框输入消息内容，输入后先核对文字是否完整、是否混入了搜索词或多余字符。输入错误就清空重输，不要在错误内容上追加。
6. 发送前 ask_user 确认，说明收件人和要发送的完整内容，以屏幕上显示的为准。用户没明确同意就不点「发送」；用户要改内容就改完再确认。
7. 「发送」是敏感操作，必须经过 Sentinel 确认。任何情况下都不要跳过确认、不要连点、不要用坐标盲点发送按钮。
8. 发送后核对刚发的内容是否出现在聊天记录底部。看到才算发送成功；没看到就说明失败原因（网络、被拦截、内容仍在输入框），不要重复发送同一条。
9. 全程只发用户给的那一条内容，不代读、不转述聊天记录，不自己追加表情、链接或第二条消息。

finish 的 summary 写：收件人、是否发送成功、失败时的原因和当前停留位置。
